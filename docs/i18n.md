# Internationalization (i18n)

English is the base language, Spanish (es-ES) is the second one. The language is chosen in
**Settings -> General -> Language** (English / Español / System default; default: English).
The tray menu texts follow it too (Rust command `set_tray_labels`).

## How it works

- `src/lib/i18n.ts` is pure TypeScript (no Svelte, no Tauri): `t(key, vars?)`, `tk(key, vars?)`,
  `setLocale`, `getLocale`, `resolveLanguage`. It can be imported from components, stores and plain modules.
- Dictionaries are flat maps, one file per **area**: `src/lib/locales/en/<area>.ts` and
  `src/lib/locales/es/<area>.ts`. `locales/en/index.ts` and `locales/es/index.ts` spread them.
  Areas: `app, topbar, sidebar, agents, usage, grid, pane, palette, dialogs, settings, store, policy, model, terminals, tray, providers, git`.
- `Key` is `keyof typeof en`, so `t('typo.here')` is a compile error. `es` is typed `Record<Key, string>`,
  so a key missing in Spanish is a type error in `npm run check` (svelte-check).
- Lookup order: current language -> English -> the key itself.
- There is no reactivity inside `t()`. Instead, `App.svelte` wraps the whole UI in
  `{#key app.settings.language}`: changing the language re-mounts every component. Terminals are not affected
  (xterm instances live in `terminals.ts`; `PaneView` unmounts/mounts their DOM, the processes keep running).
  The Settings dialog stays on the same section (`app.settingsTab`).
- Consequence: **never call `t()` at module top level** (it would run once at import time, in English).
  Call it in a component `<script>` (re-run on each mount), in a function, in a `$derived`, or in the template.
  Tables of labels must be built inside the component or inside a function, not as a module constant.

## Add a string

1. Pick the area (the file/component it lives in) and a key `area.component.thing`.
2. Add it to `locales/en/<area>.ts` **and** `locales/es/<area>.ts` (same key, same `{vars}`).
3. Use it: `{t('sidebar.activeAgents', { n: list.length })}` in templates, `t('...')` in scripts.
4. `npm run check`, `npm test`, `npm run i18n:check`.

```ts
// locales/en/sidebar.ts                      // locales/es/sidebar.ts
export default {                              export default {
  'sidebar.activeAgents': 'Active agents ({n})',  'sidebar.activeAgents': 'Agentes activos ({n})',
} as const;                                   } as const;
```

## Add a language

1. Add the code to `Locale` and `LOCALES` in `i18n.ts`, and to `LanguageSetting`/`LANGUAGE_SETTINGS` as needed.
2. Create `locales/<code>/` with one file per area plus `index.ts` (copy the `es` ones; `Record<Key, string>`).
3. Register it in `dicts` in `i18n.ts`, in `resolveLanguage` (system language) and in the selector in `SettingsGeneral.svelte`
   (language names are written in their own language), plus `scripts/i18n-check.mjs` (`for (const lang of [...])`).
4. Add the tray texts (`tray.*`) and run the checks.

## Naming rules

- Keys: `area.component.thing`, lowercase area, then camelCase segments: `settings.general.closeLabel`, `usage.bar.resetsIn`.
  The first segment must be the area (= the file name); `i18n:check` enforces this.
- Suffix conventions: `...Label` (title of a row), `...Hint` (small explanation), `...Aria` (aria-label), `...Title` (tooltip),
  `...Placeholder`, `...Empty` (empty state), `...Toast`.
- Dynamic keys: build them with `tk(\`agent.status.${status}\`)` and define every possible key
  (`agent.status.busy`, `agent.status.idle`, ...). `i18n:check` treats keys under a `tk(\`prefix.${` template as used.
  Use `t()` for everything that is static.
- Do not put plurals in keys: write `"{n} items"` or two separate keys (`...One` / `...Many`) chosen in code.

## Rules for texts

- **No string concatenation.** `t('a') + ' ' + name` breaks word order in other languages. Use `{vars}`: `'Account "{name}" removed'`.
- **No sentences split across keys** (before/after a link or an icon). Keep one sentence per key; if markup is needed,
  split into two full sentences or keep the markup outside the sentence.
- Keep the `{vars}` identical in every language (the test and `i18n:check` fail otherwise). Translate the words around them, never the names.
- Do not translate: technical identifiers, shell names (PowerShell, bash, cmd, WSL), protocol names (SSH, MCP, JSON), file paths
  and commands (`~/.ssh/config`, `/login`), keyboard key names (Ctrl, Shift, Esc), CSS/ids, the product name **Orchestra**,
  and agent kind names coming from data (`obrero`, `critico`, ...). Names of themes and fonts are proper nouns too.
- Terminal output and agent output are never translated.
- Comments in code can stay in Spanish; documentation is in English.
- A line that must stay in English on purpose can carry the comment `i18n-ignore` (the heuristic scan skips it).

## Spanish style

- Use **tú** (informal) consistently; natural wording, not literal: "Agentes activos", not "Agentes que están activos".
- Sentence case for labels, same punctuation style as English (ellipsis `...` stays `...`).
- Glossary:

## Checks

- `npm run check` - svelte-check; a key missing in Spanish is a type error.
- `npm test` - includes `src/lib/i18n.test.ts` (fallback chain, interpolation, parity, `tk`, locale switch).
- `npm run i18n:check` - exit 1 if (a) the dictionaries are inconsistent (missing/extra/empty/`{var}` mismatch/bad key names/duplicates)
  or (b) a `t()` key is not defined or a defined key is never used. Part (c) is a **heuristic** listing text that is still hard-coded
  in `.svelte` templates (text nodes, `placeholder|title|aria-label|alt|label` attributes, string literals in `{expressions}`)
  and in `.ts` (`toast(...)`, `label:`/`hint:`/`title:`/`sub:`/`what:`/`text:`/`message:`/`error:` literals), as `file:line: text`.
  Options: `--summary` (counts per file), `--strict` (also fail on (c)), and path fragments to focus on your files:
  `node scripts/i18n-check.mjs components/Sidebar lib/store`.
